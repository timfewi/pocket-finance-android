# Optional local category suggestions

The public app builds without private Git access, credentials, a model download, or an inference service. Its `pocket-category-provider` 0.1.0 implementation returns `unavailable`. Manual category selection, receipt review, and explicit saving work with that result.

The private `pocket-finance-agent` checkout can supply the same package and API through a developer-selected Cargo patch. Its source remains in that separate checkout; do not copy it, model files, prompts, or receipt data into this repository. The public application never uses an AI result as permission to save.

The verified private library is recorded at commit
`111936e4b1a276e50ccc550e9412e05cd57c6d15` in that private repository. Update your
authorized checkout to that revision or a deliberately reviewed successor before
configuring the local patch.

## Shared boundary

Both implementations expose:

```rust
pub struct CategoryChoice { pub id: String, pub label: String }
pub struct CategorySuggestion {
    pub category_id: Option<String>,
    pub status: SuggestionStatus,
}
pub enum SuggestionStatus { Suggested, Unavailable, Failed }
pub async fn suggest_category(
    ocr_text: &str,
    categories: &[CategoryChoice],
) -> CategorySuggestion;
pub fn provider_name() -> &'static str;
```

The DTOs support Serde. JSON uses `categoryId` and the statuses `suggested`, `unavailable`, and `failed`. `provider_name()` is for developer diagnostics and tests. The UI receives a suggestion or a nonblocking unavailable/failed state; it must preserve manual edits and saving. The host validates a returned ID against its current categories again before displaying or accepting it.

A category is only a suggestion. No implementation of this interface supplies an authoritative amount, date, receipt total, or saved status. Receipt fields are validated separately, and the user confirms the final record.

## Select a local private checkout

Run from this repository's root after installing its pinned Rust toolchain. The sibling checkout below must already be available to you through your own authorized access:

```sh
scripts/private-agent.sh configure ../pocket-finance-agent
scripts/private-agent.sh cargo check -p pocket-finance-android
scripts/private-agent.sh run scripts/android-env.sh npm run tauri -- android build --debug --target aarch64 --apk --ci
```

`configure` accepts any local checkout path, including a relative path. It creates ignored `artifacts/private-agent.toml` with that checkout's resolved local path. The directory and config are generated by setup, not missing tracked files. The script does not clone repositories, fetch a model, or configure credentials. The `cargo` subcommand passes the override explicitly. `run` temporarily installs ignored `.cargo/config.toml` so child Cargo processes launched by npm/Tauri discover the same override. Outside either wrapper operation, plain `cargo` uses the public stub. Move the checkout and rerun `configure` to update the path.

The root manifest patches the crates.io package to the public stub by default. The stub is excluded from workspace membership: two path packages with the same name and version cannot both be workspace resolution roots without a Cargo lockfile collision. It remains a normal dependency of the host. Run the stub's own tests with:

```sh
cargo test --manifest-path crates/category-provider/Cargo.toml
```

The private graph may require different dependency versions. The wrapper snapshots the public `Cargo.lock` and restores it on normal exit, errors, and handled signals; `run` also removes its temporary config. Build artifacts and the selected config stay under ignored directories. Do not run another Cargo command in this checkout concurrently with the wrapper. A forced process kill or power loss can prevent cleanup. In that case, first verify no wrapper/Cargo process remains, restore `artifacts/private-agent-running/Cargo.lock` to the root if that backup exists, remove the temporary `.cargo/config.toml` only if it carries this script's generated-file comment, and remove the stale `artifacts/private-agent-running` directory. Review `git diff -- Cargo.lock` before committing.

Disable the explicit override with:

```sh
scripts/private-agent.sh disable
```

`run` refuses to overwrite any existing `.cargo/config` or `.cargo/config.toml`, preserving those files byte for byte. Use `cargo` for explicit Cargo invocations when you already have local configuration; merging a custom config requires developer review. No global Cargo configuration is changed. Complete the normal [Tauri/Android setup](ANDROID.md) before running the Android packaging command above. A full private-provider debug APK was verified as described below; phone execution and native model inference are separate checks.

## Private runtime behavior and limits

The private provider uses the existing local model backend. Desktop use requires an already running, app-supervised local GGUF service and a trusted configured model path; it never starts a server or downloads weights. The private checkout's provider README documents its local runtime setup. Missing files, unavailable service, cancellation, or timeout return `unavailable`. Malformed input/output or an ID outside the supplied allowlist returns `failed`. Neither result disables manual saving.

Requests are bounded to 8,192 OCR bytes, 32 categories, 96 bytes per category ID, 160 bytes per label, 64 generated tokens, and a five-second request deadline. Oversized OCR is rejected rather than silently truncated. Output must contain exactly one `categoryId` field with an exact allowlisted ID or null; duplicate/extra fields are rejected. Receipt text and labels are untrusted input. No receipt content, prompts, or backend error details are logged or returned by the provider.

A deadline releases the caller and requests cooperative cancellation; it does not prove native model computation stopped immediately. The trusted app must supervise the model process and prevent receipt/prompt logging there as well. A valid category ID can still be the wrong category. The earlier finance-agent research did not establish production-quality model reasoning, and this suggestion-only integration makes no accuracy claim.

On Android, the private provider returns `unavailable` unless trusted app code installs an appropriate local backend. It provides an injectable backend boundary for that future work; this milestone does not package an Android GGUF runtime, model, or inference server. Android model latency, memory use, and category accuracy are unmeasured.

## Verification scope

A separate synthetic Cargo harness compiled the shared API against both implementations and observed `public-no-model` by default and `private-local-gguf` with the config patch, including Cargo launched by a child command in `run` mode. Lockfile checksums were unchanged after success and a failing Cargo command; temporary config cleanup and preservation of a preexisting config were checked. This verified config precedence rather than assuming it. Three public stub tests and seven private tests passed; private tests cover exact allowlists, malformed and duplicate fields, missing model, backend failure, oversized inputs, and the deadline.

A Linux smoke with the original Qwen3-0.6B Q8_0 model returned `suggested` / `household` for a fixed synthetic bread-and-apples grocery receipt. The category was allowed but semantically wrong. Missing-model execution returned `unavailable`. The private library also passed `cargo check -p pocket-category-provider --target aarch64-linux-android` from its own checkout, with the desktop GGUF HTTP backend excluded on Android. These checks establish the optional inference/fallback paths and library cross-compilation, not category accuracy or physical Android support.

## Verified private-provider APK

On 2026-11-05, the full Tauri ARM64 debug build succeeded on Linux using the pinned toolchain in [ANDROID.md](ANDROID.md). Cargo metadata captured while the wrapper was active resolved the host's dependency to the private `pocket-category-provider` 0.1.0 package; the native compilation log confirms that private source was compiled. The packaged native library's SHA-256 matched the newly linked private library, and Android's `apksigner verify --verbose` verified the APK's development v2 signature.

The local archive is `artifacts/apk/private/pocket-finance-private-arm64-debug.apk`, **177,282,442 bytes**, SHA-256:

```text
12709abef0326bb018bc02e604b89a83eb695dacb3851d5e8b0547aa3cf84ab8
```

Build logs, Cargo metadata, checksums, signature verification, and `verification.json` are generated locally under ignored `artifacts/apk/private/`. They are not public source artifacts. The separately archived public debug/release APK checksums and the public `Cargo.lock` checksum remained unchanged. The wrapper removed its temporary config. The usual generated debug APK path now contains whichever variant was built most recently; use the explicitly named public/private archives when comparing them.

With `JAVA_HOME`, `ANDROID_HOME`, and any required Gradle/proxy settings configured as described in the Android guide, the verification command was:

```sh
mkdir -p artifacts/apk/private
scripts/private-agent.sh configure ../pocket-finance-agent
CARGO_TARGET_DIR="$PWD/artifacts/android-target" CARGO_BUILD_JOBS=4 \
  scripts/private-agent.sh run scripts/android-env.sh sh -c \
  'cargo metadata --format-version 1 --filter-platform aarch64-linux-android > artifacts/apk/private/cargo-metadata.json && npm run tauri -- android build --debug --target aarch64 --apk --ci'
```

The generated debug APK was then deleted and the same build flags rerun to remove obsolete ZIP bytes retained by incremental packaging. That second successful build produced the archived checksum above. This is a development APK, not a private-provider release build or an installed-device test. No Android model runtime is bundled, so the private provider returns `unavailable` until trusted app code installs one; manual review and saving remain the intended fallback.
